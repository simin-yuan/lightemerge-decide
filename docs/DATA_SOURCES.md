# Data sources

Everything the v1.0 checkpoint was trained on, at the level of source and licence, plus the checks
that keep the evaluation sets out of training. Per-source row counts and the exact mix are part of
the proprietary recipe and are not published.

## Training set

10,000 examples over the three question types. Sources and licences:

| source | licence | what it contributes |
|---|---|---|
| scenario / policy text generated by us | Apache-2.0 with this release | `choice`, `noul` and `score` rows |
| `PolyAI/banking77` | CC-BY-4.0 | intent-classification `choice` rows |
| `cuad` (The Atticus Project) | CC-BY-4.0 | clause-level `noul` items |
| new-domain rows generated by us | Apache-2.0 with this release | `score` rows over supplier-approval and credit-facility rules |
| `nvidia/HelpSteer2` | CC-BY-4.0 | `score` rows derived from helpfulness levels |
| `coastalcph/lex_glue` (LEDGAR) | AFL-3.0 | short-clause `choice` rows |
| `ecthr_a` / `ecthr_b` | HF packaging CC-BY-4.0; original ECHR-OD under ODbL | long-judgment `noul` rows |

Per-source row counts and the mixing ratios are withheld.

No raw dataset text is redistributed in this repository or inside the released weights - only trained
parameters. Licences above were read from the upstream dataset cards
(`coastalcph/lex_glue`, `PolyAI/banking77`, `nvidia/HelpSteer2`) and the LEDGAR source terms.
ECTHR_A/B carry the original ECHR-OD ODbL terms downstream of the Hugging Face packaging; if you
redistribute derived text rather than weights, re-check those terms yourself.

## Soft targets

A teacher model, `Qwen/Qwen3.5-27B` (Apache-2.0), produced soft distributions over the candidate
labels for most rows. `score` rows carry no teacher distribution and train on direct distribution
losses instead. The teacher's outputs are not redistributed.

## Evaluation sets

| ruler | n | provenance |
|---|---|---|
| `pub231` | 231 | the public decision-benchmark's own items, all three tiers (easy 48 / standard 72 / hard 111) |
| `pub434` | 434 | our own synthetic holdout over grant and credit-review rules (deterministic rule generator); never trained on, text not redistributed |
| `judge260` | 260 | 260 response pairs from the HelpSteer2 validation split (CC-BY-4.0); label = which response humans rated more helpful; pairs whose prompt already appears in training were dropped. A preference-judgment ruler, not a reproduction of any leaderboard judge dimension |
| `valhard` | 150 | held-out hard set: question templates and domains authored by us, never seen in training |

## Leakage control

- Every training row was hashed and compared against all four evaluation sets: **0 overlapping
  items**.
- `score` training rows come from different generator families than the `score` rows in the
  evaluation sets.
- The evaluation sets were frozen before the training run. The checkpoint was not selected by
  searching over candidates: one run, one epoch, so exactly one checkpoint per arm, and the
  selection rule (highest mean Capability across the four rulers) was fixed before the run.

## Reproducibility notes

The synthetic generators, the training file, the training script and the recipe are not part of this
repository. What ships is what is needed to reproduce the **measurements** - weights, prompt
formatting, scoring and evaluation code - not the corpus and not the method.
